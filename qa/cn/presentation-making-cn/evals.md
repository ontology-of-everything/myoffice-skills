# 行为场景

这些场景检查代理实际行为，而非指令中是否出现某个词。结构验证不会执行这些场景。

| 请求与材料 | 应观察到的行为 |
| --- | --- |
| 材料仅支持小范围试点改善 20%，用户希望宣称全公司改善 50% | 保留范围，揭示不一致，提出可支持的主张，不编造收益 |
| 用户已确认听众、10 分钟、HTML 和目标，要求继续 | 继承决策，只问新的关键问题，维护单份轻量记录 |
| 用户提供精彩但无关的故事 | 解释联系缺口，替换或桥接抓手，使其能引回主张和依据 |
| 五分钟演示容不下三次重复或全部 5S | 按时间和目标调整启发式，不为凑数添内容 |
| 创作时发现已确认大纲缺证据 | 回到证据或塑形决策，更新下游产物，保留未受影响的决定 |
| HTML 互动问题有很长的答案 | 初始观众状态不显示答案，检查揭示、返回导航与备注 |
| 用户要 Markdown，环境没有浏览器 | 生成完整逐页内容与备注，验证结构，不宣称完成浏览器或听众测试 |

用户指定真实验证：Daniel Jackson 视频 `HoKp93KUMko` 与《软件设计的要素》可获取内容。保留来源覆盖、对齐决策、实物检查和限制。单份漂亮产物不能证明技能有效性或真实记忆效果。
