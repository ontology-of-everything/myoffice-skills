## 1. Winston 公式

**原则：**沟通质量 = f（知识、练习、天赋），其中天赋是最小的因素。

**认知依据：**精通来自知识和练习，而非天生才能。任何人都可以通过学习启发式并有意识地应用它们，成为优秀得多的沟通者。

**文字稿示例：**
> “关键在于你有多少知识、用这些知识练习了多少，以及你天生的才能；请注意，T（天赋）非常小。”
>
> Winston 以 Mary Lou Retton 的故事说明：这位天赋顶尖的奥运选手滑雪不如 Winston，因为他拥有 K（知识）和 P（练习）。“如果你拥有适量的知识，就能比那些可能具有天生才能的人进步得多。”

**所有格式的应用：**

- **所有格式：**把写作当成有可学习规则的技能，而不是依赖灵感的艺术。有意识地应用具体启发式，而不是“凭感觉”写作。

## 2. 赋能承诺

**原则：**每篇沟通材料都必须开头就告诉受众：结束时他们将知道、能够做到或理解哪些现在还不知道的事情。这就是它的存在理由。

**认知依据：**人们需要投入注意力的理由。赋能承诺创造认知契约。笑话开头会失败，因为受众尚未适应演讲者的声音和认知参数。

**文字稿示例：**
> “你应该从赋能承诺开始。要告诉人们，在这一小时结束时，他们将知道哪些开始时还不知道的事情。”
>
> Winston 自己的示例：“在这 60 分钟结束时，你们将知道一些现在还不知道的演讲知识，其中有些知识会改变你们的生活。”

**硬性规则：**绝不要用笑话开头。开场笑话会冷场，因为“人们还在收起笔记本电脑，还在适应你的说话参数”。

**按格式应用：**

| 格式 | 应用方式 |
| --- | --- |
| **演讲稿** | 第一段口头内容必须是赋能承诺。不清嗓子，不说“早上好，感谢邀请”。 |
| **文章** | 开头段落说明转变：“读完这篇文章，你将理解 X。”除非轶事包含承诺，否则不要用轶事导语。 |
| **电子邮件** | 主题行就是赋能承诺。正文第一句强化它。例如主题：“读完后，你将确切知道如何修复第三季度管线。” |
| **社交媒体** | 第一行是承诺。钩子是承诺而非标题党：“这里有件会改变你思考 X 的事情。” |
| **幻灯片提纲** | 第 1 页（标题/合作者之后）：一句赋能承诺，口头说出，不要硬塞进幻灯片。 |

## 3. 循环

**原则：**全文中必须至少三次用有意义的不同方式陈述核心论点。

**认知依据：**任何时刻约有 20% 的受众处于“迷雾”状态。为确保每个人吸收核心观点的概率足够高，必须多次循环表达。

**文字稿示例：**
> “有人说，告诉他你要告诉他的事；再说一遍；然后像对待不聪明的人一样说第三遍。但关键是……任何时刻，大约 20% 的人都会处于迷雾状态。所以，要确保每个人都理解，必须说三次。”

**按格式应用：**

| 格式 | 应用方式 |
| --- | --- |
| **演讲稿** | 在赋能承诺中陈述论点（循环 1）；在正文中从不同角度或用例子重述（循环 2）；在贡献/结尾重述（循环 3）。 |
| **文章** | 引言中提出论点（循环 1）；在核心论证或中点后重新框定（循环 2）；结论中全力重述（循环 3）。每次使用不同措辞和不同例子/框架。 |
| **电子邮件** | 超过 3 段时：第 1 句提出请求/要点（循环 1），正文强化（循环 2），结尾句重述（循环 3）。短邮件清楚说一次，再用不同措辞在结尾提出请求。 |
| **社交媒体** | 第一行 = 论点；中间 = 例子或重新框定；最后一行 = 有力形式的论点。 |
| **幻灯片提纲** | 早期页、中间页和贡献页各用一种不同方式表达同一核心观点。 |

## 4. 筑篱笆

**原则：**明确说出你的观点不是什么，以及它与可能混淆的观点有何不同。

**认知依据：**观点存在于相似观点组成的地景中。如果不明确围出篱笆，受众就会把你的观点与已知内容混为一谈，带着错误理解离开。

**文字稿示例：**
> “如果你来自火星，我要教你什么是拱，我可能会说，这就是拱；但不要把它和其他东西混淆……这不是拱，那也不是拱。我是在围绕观点筑篱笆，好让它区别于别人的观点。”
>
> 技术示例：“我的算法看起来可能和 Jones 的算法相似，但他的算法是指数级，而我的算法是线性的。”

**按格式应用：**

| 格式 | 应用方式 |
| --- | --- |
| **演讲稿** | 介绍核心观点后加一节：“这听起来可能像 X，但它不是 X。原因是……” |
| **文章** | 用一段或小节说明“这不是什么”。直接比较：“与执行 Z 的 Y 方法不同，这种方法执行 W。” |
| **电子邮件** | 用一句话筑篱笆：“明确说，我不是提议推迟发布，而是提议改变发布顺序。” |
| **社交媒体** | “这**不是**关于[常见误解]，而是关于[实际观点]。” |
| **幻灯片提纲** | 加入“这是什么/不是什么”的对照页，文字保持最少。 |

## 5. 口头标点

**原则：**提供宣布结构的明确过渡地标，让短暂走神的人可以重新登上思路列车。

**认知依据：**人们会进出注意状态。没有结构路标，一个走神 30 秒的人会在余下内容中迷失。口头标点在沟通中提供可重新进入的“接缝”。

**文字稿示例：**
> “需要提供一些地标，宣布现在是重新上车的好时机。”
>
> Winston 示范：“第一件要做的是讨论如何开始。然后处理四个样本；在这四个样本中，我已经谈了第一个观点——循环。第二个观点是筑篱笆；现在第三个是口头标点。所以我在列举并提供数字，让你感觉演讲中存在接缝。”

**按格式应用：**

| 格式 | 应用方式 |
| --- | --- |
| **演讲稿** | 使用明确的编号过渡：“那是第一点。现在进入第二点。”绝不依赖隐含的流动。 |
| **文章** | 使用小标题作为口头标点，也使用过渡句：“既然已经确立 X，现在转向 Y。” |
| **电子邮件** | 多点邮件使用编号列表或明确过渡：“第一点……第二点……最后……” |
| **社交媒体** | 线程用换行和编号。线程中的每篇都用重新定位的短语开头。 |
| **幻灯片提纲** | 定期加入“路线图”页，显示结构中的当前位置（例如在列表中突出当前部分）。 |

## 6. 校准问题与 7 秒规则

**原则：**提出经过仔细校准的问题——不能明显到回答会令人尴尬，也不能困难到没人能回答。然后完整等待 7 秒。

**认知依据：**问题迫使人主动参与认知。7 秒等待制造有益的不适，激活思考。大多数演讲者 2 秒后就放弃，失去参与收益。

**文字稿示例：**
> “既然势头不错，你能猜出第四个观点是什么吗——能帮助人们重新上车的观点？”
> [观众回答：“提问。”]
> “我会提一个问题——可以有多少无声空气？我能停多久？我数了 7 秒。对我而言像永恒……但这是等待回答的标准时间。”
>
> “问题必须谨慎选择。不能太明显，否则人们不好意思说；答案又不能太难，否则没人有话可说。”

**按格式应用：**

| 格式 | 应用方式 |
| --- | --- |
| **演讲稿** | 逐字写出问题，后接 `[PAUSE FOR 7 SECONDS]`。若无人回答，写好后续应对。 |
| **文章** | 提出反问，然后换段（文字版停顿），再回答。 |
| **电子邮件** | 用真实问题结束一节，单独成行，四周留白。 |
| **社交媒体** | 以校准问题结尾。不要用“你怎么看？”（太模糊），而要用具体、可回答的问题。 |

## 7. 时间与地点

**原则：**沟通环境很重要。演讲的最佳时间是上午 11 点；房间必须明亮；场地要提前勘察；座席应超过一半坐满。

**认知依据：**昏暗房间传达睡眠信号。饭后时段让人困倦。空房间传达无关紧要。陌生场地会造成本可避免的意外。

**文字稿示例：**
> “上午 11 点？是的。因为那时 MIT 大多数人醒着，几乎没人重新睡着。”
>
> “灯光变暗时……它向我们人类发出应该睡觉的信号。”
>
> “每次去一个地方演讲，我首先要求主人带我去演讲场地。”
>
> 关于填满空间：“如果大厅里只有 10 个人，每个人都会想，究竟有什么更有趣的事，让这里几乎没人？”

**按格式应用：**

| 格式 | 应用方式 |
| --- | --- |
| **演讲稿** | 在备注中加入演讲前检查表：灯光全开、场地勘察、房间大小合适。 |
| **文章** | 把“时间与地点”理解为发表语境：读者在哪里遇到它？早间通讯还是深夜博客？相应调整语调。 |
| **电子邮件** | 在最佳阅读时间发送。不要在周五晚发送关键沟通。“场地”就是收件箱——主题和预览文字是“明亮房间”。 |
| **幻灯片提纲** | 制作准备的第一条备注：“灯光全开。不要暗模式。全亮环境下文字必须可读。” |

## 8. 黑板原则（告知模式）

**原则：**目的为告知或教学时，优先使用类似黑板的渐进、手写式揭示，而不是预制幻灯片。幻灯片用于**展示**观点；黑板用于**教学**。

**认知依据：**黑板在教学上更优有三个属性：

1. **图形质量**——容易绘制和标注。
2. **速度属性**——书写速度匹配吸收速度；幻灯片翻得太快。
3. **目标属性**——让演讲者的手有事可做，并给受众一个焦点。

**文字稿示例：**
> “我相信，当目的为告知时，这是演讲的正确工具。目的为展示时，幻灯片很好。”
>
> “你在黑板上的书写速度大约就是人们吸收观点的速度。如果快速翻过一堆幻灯片，没人能跟上。”

**按格式应用：**

| 格式 | 应用方式 |
| --- | --- |
| **演讲稿** | 教学演讲中安排渐进揭示：逐项显示项目符号，或使用现场白板。绝不要一开始展示完整图表。 |
| **文章** | 渐进揭示复杂性。不要先给出完整框架再解释；跨段落逐步搭建。 |
| **幻灯片提纲** | 将幻灯片标为 `[INFORMING]` 或 `[EXPOSING]`。告知页渐进构建，展示页可以更完整。 |

## 9. 共情映射

**原则：**当受众能在身体上共情演讲者的动作时，他们会更深地参与。身体动作和现实演示激活镜像神经元，形成具身理解。

**认知依据：**观察身体动作时，镜像神经元会放电，让受众仿佛正在执行动作。静态幻灯片或图片无法复制这种效果。

**文字稿示例：**
> “当你坐在那里看我在黑板上写字时，我相信你脑中的镜像神经元会被激活，你会感觉自己正在黑板上写字。尤其当我讲钢球向这边、再向那边运动时，你会感觉自己就是我，幻灯片做不到这一点。”

**按格式应用：**

| 格式 | 应用方式 |
| --- | --- |
| **演讲稿** | 写出身体演示。加入手势、移动和道具操作的舞台指示。写受众应感受到什么，而不只是看到什么。 |
| **文章** | 使用生动、动觉语言：描述动作、身体感受和空间关系。“想象握住方向盘，感受它与握力对抗”胜过“方向盘抵抗扭矩”。 |
| **电子邮件** | 使用具体、以行动为导向的语言：“打开仪表板，点击导出按钮”而不是“导出功能可用”。 |

## 10. 道具规则

**原则：**实体道具会被不成比例地记住。它们把抽象观点锚定到具体、有形的物体上。

**认知依据：**道具利用共情映射，制造叙事张力（如易卜生的腹式火炉），并成为多年后人们记住的东西。

**文字稿示例：**
> Winston 谈易卜生的 *Hedda Gabler*：“戏一开始有一只腹式火炉……随着戏剧张力增加，你看到这份手稿，这个易卜生巧妙运用的道具，就知道要发生什么，因为戏继续下去，火越来越大、越来越热。”
>
> Jim Glass 20 年后回忆 Winston 的演讲：“哦，对，我记得那场演讲。就是你弄断指示棒的那场。”
>
> “道具往往是人们记住的东西，这很惊人。”

**按格式应用：**

| 格式 | 应用方式 |
| --- | --- |
| **演讲稿** | 编排一个道具时刻。说明道具是什么、何时出现、如何在身体上展示观点。道具是抽象概念的有形锚点。 |
| **文章** | 使用反复出现的具体物体或图像作为文学“道具”，贯穿全文回到它。易卜生的火炉就是你的反复隐喻。 |
| **社交媒体** | 以体现抽象观点的照片或具体物体为开头。 |

## 11. 幻灯片纪律

**原则：**幻灯片必须删减到绝对最低限度。去掉背景、徽标和标题（改为口头说出）。最小字号 40–50 磅。不要用激光笔（使用内嵌箭头）。把打印幻灯片铺在桌上检查密度。

**认知依据：**单一语言处理器约束（见规则 26）。幻灯片上的每个词都会与演讲者争夺受众唯一的语言处理器。

**文字稿示例：**
> “幻灯片太多，字也太多。你怎么知道？我的回答是，因为这总是事实。”
>
> “第一步是去掉背景垃圾；第二步是去掉文字……去掉徽标……去掉标题。”
>
> 关于激光笔：“不用转头就不能使用激光笔……一转头，就失去与受众的联系。”
>
> 字号测试：“测试容易辨认的最小字号……40 或 50，我认为差不多。”
>
> 密度测试：“我让他们打印出来铺在桌上。这样很容易看出演讲是否太沉重。”

**按格式应用：**

| 格式 | 应用方式 |
| --- | --- |
| **幻灯片提纲** | 每页必须通过：(1) 无背景艺术/徽标/水印；(2) 约不超过 10 个词；(3) 40 磅以上；(4) 演讲者会说标题时，页上不要标题；(5) 使用内嵌箭头，绝不使用激光笔指示；(6) 打印铺桌测试密度。 |
| **文章** | 类比地删除填充词、装饰性语言和不必要标题。每段都应有“空气”。 |
| **电子邮件** | 无情删减。若邮件超过手机一屏，就是过重幻灯片组的邮件版本。 |
| **社交媒体** | 最大密度 = 每篇一个观点。线程不应试图覆盖一篇文章的内容。 |

## 12. Hapax Legomenon

**原则：**每篇沟通材料恰好有一次机会展示刻意令人不知所云或复杂的内容。用它说明某件事复杂到无法理解。每场演讲、每篇论文、每本书一次。

**文字稿示例：**
> “这是一个 hapax legomenon，意思是这是演讲中恰好可以使用一次的幻灯片类型……受众无法理解它，这正是重点，但不能有很多这样的页。”
>
> 示例：阿富汗治理复杂性图。

**按格式应用：**

| 格式 | 应用方式 |
| --- | --- |
| **演讲稿** | 正好编排一个令人不知所云的视觉内容，并标注：`[HAPAX LEGOMENON: 此页刻意复杂，重点就是复杂性本身。]` |
| **文章** | 用一次刻意令人不知所云的细节（长列表、密集段落）表达关于复杂性的元观点，并向读者标明。 |

## 13. 激情原则

**原则：**当沟通者对主题表现出真实激情时，受众会受到鼓舞。

**认知依据：**Winston 的调查发现：新生受到相信他们的教师鼓舞；高年级教师受到以新方式展示问题的人鼓舞；而**每个人**都会受到展现激情的人鼓舞。

**文字稿示例：**
> “我从所有人身上看到的是：当有人对自己做的事表现出激情时，他们就受到鼓舞。”
>
> “在 AI 课上讲课时，自然会谈我觉得酷的东西，以及某个新观点多么令人兴奋。”
>
> 资源分配示例：“这不是很酷吗？你应该惊叹于某种把计算从超过太阳系寿命缩短到几秒的东西。”

**按格式应用：**

| 格式 | 应用方式 |
| --- | --- |
| **所有格式** | 代理必须表达主题为何对作者/演讲者重要。不是表演式热情（“哇！太棒了！”），而是对观点带来可能性的真实智识兴奋。采用 Winston 的“这不是很酷吗？”——具体、扎根于事实的惊奇。 |

## 14. 故事动物

**原则：**人类通过故事思考。教人思考，就是给他们所需的故事、关于故事的问题、分析故事的机制、编排故事的方法，以及评估故事可靠性的方法。

**认知依据：**从童年的童话到法律、商业、医学等职业训练，我们逐渐培养故事处理能力。故事是人类认知的基本单位。

**文字稿示例：**
> “我相信我们是故事动物。我们从童年童话开始发展理解和操纵故事的技能，并在法律、商业、医学等职业学校中持续发展。”
>
> “你要提供他们需要知道的故事、需要针对故事提出的问题、分析故事的机制、组织故事的方法，以及评估故事可靠性的方法。”

**按格式应用：**

| 格式 | 应用方式 |
| --- | --- |
| **演讲稿** | 把内容组织成有角色、张力和解决方案的故事。受众应感到叙事在推进。 |
| **文章** | 把论证组织成叙事：设定（问题）、上升行动（失败的做法）、高潮（洞见）、解决（方案）。 |
| **电子邮件** | 即使短邮件也受益于微型叙事：“我们试了 X。它因 Y 而失败。这是我建议的替代方案。” |

## 15. 定位

**原则：**将工作置于背景中。解释问题为何重要、还有谁在研究它、过去什么没有奏效。

**文字稿示例：**
> “回顾那些失败（口试失败）时，人们没通过口试最常见的原因就是没有定位……在背景中谈研究很重要。全世界都在研究这个问题；过去 30 年在我之前没有进展。”

**按格式应用：**

| 格式 | 应用方式 |
| --- | --- |
| **演讲稿** | 展示方案前花 1–2 分钟建立地景：谁在乎、尝试过什么、为什么困难。 |
| **文章** | 早期加入“背景”或“语境”部分。不是文献综述，而是叙事式定位问题。 |
| **电子邮件** | 一句背景：“如你所知，团队已经连续三个迭代周期在 X 上遇到困难。” |

## 16. 与陌生人练习

**原则：**绝不要只和了解你工作的人练习演讲。他们会幻觉出你的演讲中并不存在的内容。要和不了解主题的人练习。

**文字稿示例：**
> “如果人们知道你在做什么，他们会幻觉出你的演讲中并不存在的材料。”
>
> “你的导师并不是帮你调试演讲的好人选，因为他们确实知道你在做什么。”
>
> “开始练习时要说：如果你不能让我哭，我就不再把你当朋友。”

**按格式应用：**

| 格式 | 应用方式 |
| --- | --- |
| **所有格式** | 审阅草稿时，让不了解主题的人阅读。询问：“哪里不清楚？缺了什么？”领域专家会无意识地填补空白。 |

## 17. 5 分钟窗口（愿景 + 做成了事情）

**原则：**在说服性演讲（尤其是求职演讲）中，你恰好有 5 分钟建立两点：(1) 你有愿景；(2) 你做成了事情。

**认知依据：**评估者很早就做决定。如果前 5 分钟没有建立愿景和成就，后面的演讲就只是在控制损失。

**文字稿示例：**
> Winston 问同事 Delores Etter 和 Bill Weldon 选 faculty 候选人看重什么：
> “Delores 在一微秒内说，他们必须很快展示某种愿景；Bill 随即说，他们必须展示自己做成过事情。”
> “候选人有多长时间建立这两点？……5 分钟。”

**按格式应用：**

| 格式 | 应用方式 |
| --- | --- |
| **演讲稿** | 前 5 分钟必须包含：(1) 你看到而别人没看到的问题（愿景）；(2) 你取得进展的具体证据（做成了事情）。 |
| **文章** | 前两段必须建立愿景（你看到了什么）和可信度（你做了什么）。 |
| **电子邮件** | 前两句：你想做什么（愿景），以及为什么由你来做（做成了事情）。 |

## 18. 步骤列举

**原则：**要证明你“做成了事情”，列出达到目标所需的步骤，然后显示哪些已完成。

**文字稿示例：**
> “如何表达你做成了事情？列出解决问题、达成方案所需采取的步骤。”
>
> “我们需要规定某些行为，需要列举约束……作为工程师，我们必须实现一个系统……我们已经构建了这样的系统，今天就要向你们演示。”

**按格式应用：**

| 格式 | 应用方式 |
| --- | --- |
| **演讲稿** | 说明愿景后给出编号步骤，标明哪些已完成、哪些进行中。 |
| **文章** | 用路线图段落：“解决它需要三件事：A、B、C。我们完成了 A 和 B。具体如下。” |
| **电子邮件** | 用项目符号列出步骤并标注状态。 |

## 19. Winston 之星（成名框架）

**原则：**观点要被记住，需要五个都以 S 开头的要素：

1. **符号（Symbol）**——与工作相关的视觉或概念图标。
2. **口号（Slogan）**——给工作提供抓手的短语。
3. **惊喜（Surprise）**——违反受众假设的意外内容。
4. **醒目观点（Salient Idea）**——比所有其他观点都突出的一个观点（不是“重要”，而是“突出”）。
5. **故事（Story）**——工作如何完成、如何运作、为何重要的叙事。

**认知依据：**观点会争夺记忆。五个 S 创造多条提取路径，让观点更可能被回忆。

**文字稿示例：**
> Winston 关于拱学习的博士工作：
>
> - **符号：**拱本身（视觉构型）。
> - **口号：**“一次学习”——程序从每个示例中学到确定的东西。
> - **惊喜：**“不需要一百万个示例……一个示例就够。”
> - **醒目观点：**“近失例”——几乎匹配、但以一种有启发性的方式失败的示例。
> - **故事：**从模型到近失例再到学习的叙事。
>
> “这项拱学习工作变得小有名气，我当时不知道为什么。多年后才意识到，那项工作偶然具备了这颗星上的全部要素。”

**按格式应用：**

| 格式 | 应用方式 |
| --- | --- |
| **演讲稿** | 起草前识别观点的五个 S。缺少时补充发展。符号应出现在幻灯片上；口号至少说两次；惊喜应在中间三分之一处落地；醒目观点应成为受众转述给他人的唯一内容；故事应框定全场演讲。 |
| **文章** | 口号可成为标题或副标题；符号可为反复出现的图像或隐喻；惊喜放在导语或转折处；醒目观点就是论点；故事就是结构。 |
| **电子邮件** | 主题行 = 口号；第一句 = 惊喜或醒目观点。 |
| **社交媒体** | 可组织为：符号（图像）+ 口号（第一行）+ 惊喜（钩子）+ 故事（正文）。 |

## 20. 近失例

**原则：**教学或解释时，使用近失例——接近观点、但在一个具体且有启发性的地方失败的例子。

**文字稿示例：**
> 拱学习示例：“这不是拱，但差得不多，所以是近失例。”
>
> 也是一般的筑篱笆：“不要把它和别人可能认为是拱的东西混淆——这不是拱。”

**按格式应用：**

| 格式 | 应用方式 |
| --- | --- |
| **所有格式** | 解释概念时至少提供一个近失例：“你可能以为这意味着 X。接近了，但不对。差别是 Y，而 Y 正是关键。” |

## 21. 贡献式结尾

**原则：**最后一页/最后一段/最后一节必须标为“贡献”，并列举你具体贡献的内容。这不是“结论”页。“贡献”强调你做了什么；“结论”强调一般为真的东西。

**认知依据：**最后一页会在提问和人群离场时保持显示，是最后印象。把整个演示中最有价值的空间浪费在“问题？”或“谢谢”上不可取。

**文字稿示例：**
> “如果你说这是我的结论，那是完全合理的结论，但没人关心。人们关心你做了什么。所以最后一页应标为‘贡献’。”
>
> “最后一页，也就是人们提问和离场时显示的那一页，应该放你的贡献。”

**按格式应用：**

| 格式 | 应用方式 |
| --- | --- |
| **演讲稿** | 最后一页标题：“贡献”。列 3–5 项具体贡献，问答时保持显示。 |
| **文章** | 最后一节：“本文贡献”或同等标题。不要写“总之”，要说明给读者理解增加了什么。 |
| **电子邮件** | 最后一行重申具体价值或行动：“这让我们拥有此前没有的 X、Y 和 Z。” |

## 22. 反“谢谢”规则

**原则：**绝不要以“谢谢”结束。这是软弱的动作，暗示受众出于礼貌才忍受你的演讲。

**认知依据：**“当你说谢谢，更糟的是说感谢聆听，就暗示大家坚持到现在只是出于礼貌，并且强烈渴望去别的地方。”

**文字稿示例：**
> “我不建议这样做。这是软弱的动作。”
>
> Winston 展示 Bill Clinton 刻意避免“谢谢”：“有一次，他似乎几乎抿紧嘴唇，强迫自己不要说谢谢。”

**按格式应用：**

| 格式 | 应用方式 |
| --- | --- |
| **演讲稿** | 不要把“谢谢”写成最后的话。改用致敬、笑话或祝祷。 |
| **文章** | 不要以“感谢阅读”结束。以贡献或致敬结束。 |
| **电子邮件** | 邮件中用“谢谢”作为落款问候在文化上很常见，可以接受；但它只能是**结束问候**，不能是最后的实质内容。最后一个实质句应是贡献或行动号召。 |

## 23. 致敬式结尾

**原则：**向受众致敬——真诚表达对他们所处语境、所做工作或你在其环境中度过的时间的认可。

**文字稿示例：**
> “你可以向受众致敬。也就是说，可以说说你多么珍视在一个地方的时光。”
>
> Winston 示范：“在这里很开心。看到你们在 MIT 做的事情很有意思。你们提出的问题让我受到很大激发和启发。”
>
> 他的实际结尾：“我很高兴你们在这里……我向你们致敬。”

**按格式应用：**

| 格式 | 应用方式 |
| --- | --- |
| **演讲稿** | 写出真诚的致敬：认可受众的专业、对主题的投入或参与质量。 |
| **文章** | 以认可读者的投入收尾：“如果你读到这里，你就明白这为何重要——而这种理解本身就是第一步。” |

## 24. 笑话位置规则

**原则：**笑话开头会失败（受众尚未适应），结尾会有效（受众已调谐并准备好）。

**文字稿示例：**
> 开头：“我不建议这样做……演讲开始时，人们还在收电脑，正在适应你的说话参数……通常会冷场。”
>
> 结尾：Doug Lenat 的建议：“我总是用笑话结束，这样人们会觉得整个过程都很有趣。”

**按格式应用：**

| 格式 | 应用方式 |
| --- | --- |
| **演讲稿** | 前 2 分钟绝不要写笑话。最后 2 分钟的笑话有效。 |
| **文章** | 机智或令人意外的结尾句有效；“搞笑”的开头句通常无效。 |

## 25. 合作者位置规则

**原则：**在第一页而不是最后一页致谢合作者。最后一页的合作者名单会削弱个人贡献。

**文字稿示例：**
> “演讲最后展示一长串合作者名单，会让人失望，因为它暗示没人知道……你到底做了什么重要的事？”
>
> “应该在哪里做？不是最后一页，而是第一页。”

**按格式应用：**

| 格式 | 应用方式 |
| --- | --- |
| **演讲稿** | 第 1 或第 2 页列合作者；最后一页只放贡献。 |
| **文章** | 在第一节或脚注中致谢，不要放在结尾段。 |

## 26. 单一语言处理器约束

**原则：**人类只有一个语言处理器。如果它在阅读，就不能同时聆听；如果它在浏览，就不能吸收演讲者的话。

**认知依据：**这是支配所有幻灯片设计、文字密度决策和竞争信息通道选择的主约束。

**文字稿示例：**
> “我们人类只有一个语言处理器。如果语言处理器正在浏览网页或阅读邮件，你就会分心。”
>
> “我们只有一个语言处理器，可以用来阅读，也可以用来听演讲者。”
>
> 学生实验：“受试者记住的是他说的话，还是幻灯片上读到的？答案是他们在幻灯片上读到的……有位受试者说，我希望你没说那么多，那很分心。”

**按格式应用：**

| 格式 | 应用方式 |
| --- | --- |
| **演讲稿** | 演讲者说话时，绝不要让受众阅读密集文字。若文字页不可避免，先停下来让受众阅读，再讲话。 |
| **幻灯片提纲** | 幻灯片是佐料，不是主菜。页上文字要少，让受众听演讲者。 |
| **文章** | 不要迫使读者处理两个竞争的信息流（如密集脚注与正文竞争，或需要并行阅读的侧栏）。 |

## 按格式速查

### 演讲稿

1. 以赋能承诺开头，绝不以笑话开头
2. 循环论点 3 次
3. 围绕核心观点筑篱笆
4. 使用口头标点（编号过渡）
5. 写出带 `[PAUSE FOR 7 SECONDS]` 的校准问题
6. 检查时间与地点（灯光、场地、大小合适）
7. 教学用黑板/渐进揭示，展示用幻灯片
8. 写出身体演示和道具
9. 幻灯片：无徽标、无背景、无标题、40 磅以上字体、内嵌箭头
10. 允许一个 hapax legomenon
11. 表达真实激情
12. 将工作放入背景
13. 前 5 分钟建立愿景 + 做成了事情
14. 列举步骤
15. 应用 Winston 之星（符号、口号、惊喜、醒目观点、故事）
16. 最后一页 = 贡献
17. 第一页列合作者
18. 以致敬、笑话或祝祷结束——绝不说“谢谢”

### 文章

1. 开头段落 = 赋能承诺
2. 循环论点：引言、中点、结论
3. 用一段说明“这不是什么”
4. 以小标题和过渡句充当口头标点
5. 以换段停顿呈现反问
6. 渐进构建观点（黑板原则）
7. 使用动觉、生动语言（共情映射）
8. 使用反复出现的具体图像作为文学道具
9. 保持段落透气——不要文字墙（幻灯片纪律类比）
10. 一个刻意复杂的时刻（hapax legomenon）
11. 表达真实的智识兴奋
12. 将内容框定为叙事（故事动物）
13. 尽早定位论证
14. 前两段：愿景 + 可信度
15. 用路线图段落列举步骤
16. 应用 Winston 之星
17. 最后一节 = 贡献，不要写“总之”
18. 绝不要以“感谢阅读”结束

### 电子邮件

1. 主题行 = 赋能承诺
2. 第一句强化承诺
3. 3 段以上邮件：循环要点 3 次
4. 用一句话筑篱笆
5. 多点邮件使用编号列表
6. 一句背景（定位）
7. 具体、以行动为导向的语言
8. 无情缩短——最多一屏手机
9. 最后一个实质句 = 贡献或行动号召
10. “谢谢”只能作落款，绝不能作为最后内容

### 社交媒体帖子

1. 第一行 = 赋能承诺（钩子是承诺而非标题党）
2. 第一行论点、中间例子、最后一行论点（循环）
3. “这不是关于 X，而是关于 Y。”（筑篱笆）
4. 线程使用换行和编号（口头标点）
5. 以校准问题结尾
6. 以具体图像开头（道具）
7. 每篇一个观点（幻灯片纪律）
8. 应用 Winston 之星中的口号 + 惊喜

### 幻灯片提纲

1. 第 1 页：标题 + 合作者
2. 第 2 页：赋能承诺（口头说出，不要塞满）
3. 定期路线图页（口头标点）
4. 所有幻灯片：无徽标、无背景、无杂乱内容、40 磅以上字体
5. 教学页采用渐进构建
6. 用内嵌箭头代替激光笔指示
7. 最多一页 hapax legomenon
8. 打印铺桌密度测试
9. 最后一页：“贡献”，列 3–5 个项目
10. 幻灯片是演讲者的佐料，不是主菜
