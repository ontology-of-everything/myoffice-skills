# 常见错误参考

## 相关框架

- 所有框架

本参考扩展了 `SKILL.md` 中的“误解防护”。每一项都说明 Winston 建议的正确解释、误解为何会发生，以及如何正确应用原则。

## 错误 1：“永远不要使用幻灯片”

**错误解释：**Winston 讨厌幻灯片，所以永远不要使用幻灯片。

**正确解释：**Winston 区分两种媒介：

- **板书**（白板、黑板）→ 用于*教学*（逐步建立概念和流程）
- **幻灯片** → 用于*展示*（数据、照片、复杂图表、证据）

错误在于把幻灯片当作讲稿（错误 4），或在板书更合适时仍把幻灯片作为主要教学媒介。幻灯片非常适合展示证据和数据。

**如何正确应用：**对演讲的每个部分都问：“我是在教学一个概念（→ 板书），还是在展示证据（→ 幻灯片）？”大多数演讲两者都需要。

## 错误 2：“用笑话开场”

**错误解释：**用幽默开场，让听众热身。

**正确解释：**Winston 明确说不要用笑话开场——听众还没有热身。他们不了解你的风格、节奏，也不知道你是否值得信任。开场 30 秒内冷掉的笑话会造成严重打击。

但 Winston 说可以用笑话收尾——到那时听众已经热身。他们认识你、喜欢你（如果演讲顺利），幽默会自然落地。

**不对称性正是关键：**笑话需要热身后的听众。开场是冷场，结尾是暖场。

**如何正确应用：**用赋能承诺（框架 3）开场，用笑话或致敬（框架 10）收尾。不要把两者颠倒。

## 错误 3：“禁止说谢谢”

**错误解释：**绝不能对听众说“谢谢”。

**正确解释：**“谢谢”作为你的*最后印象*——字面上的最后一句话和最后一页——很弱。它暗示听众承受了一种负担，令人难以记住。作为最后一页，它会在整个问答期间停留在屏幕上，浪费最宝贵的视觉空间。

在演讲中途作为随口致意或简短礼貌用语，“谢谢”完全没问题。禁止的是把它作为你的*收尾动作*。

**如何正确应用：**

- 最后一页 → Contributions（贡献），不要写“thank you”
- 最后一句 → 笑话或致敬，不要说“thank you”
- 演讲中途致意 → 可以（“谢谢你的问题”）

## 错误 4：“道具必须是实物”

**错误解释：**每场演讲都必须带一个真正的实物。

**正确解释：**Winston 所说的道具包括：

- 实物（有合适且相关的实物时）
- 板书（书写本身就是道具——它创造运动、调动镜像神经元并控制表达节奏）
- 现场演示（代码执行、实物演示、听众参与）
- 任何能让抽象概念具体化的身体动作

关键原则是*身体性*和*镜像神经元激活*——听众应该感觉自己正在做这件事，而不只是观看。

**如何正确应用：**问：“我能以任何方式让这个概念变得具体吗？”画出来、在板上逐步构建、现场演示，或使用实体类比，都算数。

## 错误 5：“40pt 字号不可协商”

**错误解释：**每张幻灯片上的每个字符都必须精确为 40pt 或更大。

**正确解释：**Winston 的原则是：让文字足够大，服务听众，而不是服务演讲者的备注。40pt 是适用于大多数会议规模场地的强启发式。

环境很重要：

- 大型场地（100 人以上、屏幕较远）→ 40pt 最小字号合理
- 小型会议室（10 人、屏幕较近）→ 30pt 可能足够
- 代码幻灯片 → 如果代码就是重点，带语法高亮的 24–28pt 等宽字体可以接受

**底层原则：**如果你需要缩小文字才能塞下内容，那么内容应该放进口头表达，而不是幻灯片。幻灯片是佐料——它支持你所说的内容，而不是你的讲话稿。

**如何正确应用：**从 40pt 开始。如果内容放不下，问：“这是听众必须**看到**的，还是我可以**说**的？”把口头内容移到演讲者备注中。幻灯片只保留必须视觉呈现的内容。

## 错误 6：“赋能承诺就是目录”

**错误解释：**以“今天我会先讲 A，然后讲 B，最后讲 C”开头。

**正确解释：**赋能承诺是*结果承诺*，不是议程。它告诉听众演讲结束后将*能够做什么*，而不是你将覆盖哪些主题。

**对比：**

- 议程（弱）：“今天我会先讲事件溯源，然后讲 CQRS，最后讲实现。”
- 赋能承诺（强）：“演讲结束时，你将能够判断事件溯源是否适合你的系统，并勾勒出迁移计划。”

**如何正确应用：**使用以下格式：“在这次[演讲/课程]结束时，你将能够[具体、可测试的能力]。”如果听众无法验证承诺是否兑现，它就太模糊。

## 错误 7：“贡献必须列出技术成果”

**错误解释：**贡献页用于列出论文、代码仓库或交付物。

**正确解释：**贡献回答的是：“听众现在能做什么？”——而不是“演讲者产出了什么？”每个要点都从听众视角来写。

**对比：**

- 以演讲者为中心（弱）：“发表了 3 篇论文，发布了开源库，申请了 2 项专利。”
- 以听众为中心（强）：“你现在可以评估事件溯源是否适合你的系统；你有一份迁移清单；你看过一个可运行的参考实现。”

**如何正确应用：**每条贡献都以“你”开头——这会强制采用听众视角。

## 错误 8：“提问说明听众没听懂”

**错误解释：**如果听众提问，说明演讲没有解释清楚。

**正确解释：**提问是参与的信号。Winston 的四个启发式（框架 4）明确把*提出问题*列为重新吸引听众的技巧。问答中的问题意味着人们正在思考你的观点。

关键区别在于：

- **澄清问题**（“你说的 X 是什么意思？”）→ 你的解释可能需要改进
- **延伸问题**（“如果 X，会发生什么？”）→ 演讲激发了思考，这就是成功

**如何正确应用：**欢迎所有问题。对于澄清问题，把它们记录为改进该部分的信号；对于延伸问题，把它们连接回你的框架和贡献。

## 快速参考：正确与错误的应用

| 原则 | 错误 | 正确 |
|---|---|---|
| 板书与幻灯片 | 永远不要使用幻灯片 | 用板书教学，用幻灯片展示证据 |
| 开场幽默 | 用笑话开场 | 用赋能承诺开场，以笑话收尾 |
| “谢谢” | 永远不要说 | 不要把它作为最后一页或最后一句 |
| 道具 | 必须是实物 | 任何增加身体性的东西（板书、演示、实物） |
| 字号 | 40pt 是绝对规则 | 40pt 是强默认值，按场地调整 |
| 赋能承诺 | 目录 | 具体的结果承诺 |
| 贡献 | 演讲者的产出清单 | 听众获得的新能力 |
| 听众提问 | 失败的信号 | 参与的信号 |
