# Express-Improve：让观点被听见、理解并记住

本技能建立在 Patrick Winston 的 MIT 演讲 *How to Speak* 的系统方法之上，并结合创业招募、研究演示、求职演讲和说服性对话等高风险沟通场景的实际要求。

**核心信念**：好观点不会自行传播。沟通质量 = 知识 × 练习 ×（少量天赋）。表达是一项可以系统训练的技能，不是与生俱来的才能。

---

## I. 先识别场景，再选择策略

收到用户请求时，先确定以下三件事：

**1. 这属于哪种沟通场景？**

| 场景类型 | 核心任务 | 成功标准 |
|---------|---------|---------|
| **创业招募 / 说服联合创始人** | 让对方相信你正在做正确的事，而且值得押注 | 对方主动问：“我能做什么？” |
| **研究演示 / 组会 / 答辩** | 帮助非专家理解，同时让专家相信你严谨可靠 | 问题集中于未来方向，而不是“你到底在做什么？” |
| **求职演讲** | 在 5 分钟内同时建立愿景和大量已完成的工作 | 委员会最终认为：“这个人有方向，而且已经做出了真正的成果。” |
| **投资人路演 / 路演演示** | 让听众在短时间内理解问题、解决方案和你的独特性 | 听众提出具体的后续问题 |
| **说服性对话 / 提案讲解** | 让听众从不确定转向同意并愿意行动 | 听众询问实施细节，而不是继续提出反对意见 |
| **公开演讲 / 知识分享会** | 留给听众至少一个会改变其思考方式的观点 | 会后有人主动讨论这个观点 |
| **向上汇报 / 绩效评审** | 帮助管理层快速理解你做了什么以及为什么重要 | 演示后，领导问的是“下一步是什么”，而不是“这是什么？” |

**2. 用户处于哪个阶段？**

- 还没有内容 → 进入**框架设计模式**
- 已有草稿或提纲 → 进入**诊断优化模式**
- 只需要某个具体部分的帮助（开场 / 结尾 / 一页幻灯片）→ 进入**局部重写模式**

**3. 时间限制是多少？**  
（这会影响结构密度。）

## II. 开场设计原则

> 开场决定听众是否愿意继续听。开场薄弱会拖累整场演讲。

### 核心规则

**不要用笑话开场。** 开始时听众还没有调到你的频道，笑话往往会冷场。

**第一步：做出赋能承诺**

开场唯一的任务，是回答听众心里已经存在的问题：**“我为什么应该听这个？”**

模板：
```text
“在接下来的 X 分钟里，你将学到 [具体内容]，
而且 [某个具体观点] 会改变你对 [某个具体问题] 的思考方式。”
```

创业示例：

```text
“在接下来的五分钟里，我会向你展示，为什么中国有一百万个小团队
正在面对一个真正还没有被解决的问题，
以及我们如何在短短三个月内验证出一条前进路径。”
```

研究示例：

```text
“今天我想展示一个结果，它会让你重新思考一个问题：
为什么在我们之前，所有人都假定这个前提是正确的？”
```

### 同时植入激情信号

开场时表达你对主题的真实兴奋。这不是表演，而是坦率说明你为什么觉得它酷、重要，或值得花三年时间研究。真实的投入比修辞技巧更能打动听众。

## III. 构建正文：四个核心启发式

### 1. 循环（Cycle）

从不同角度重复中心观点两到三次。这不是机械重复，而是：

* 第一次：建立概念
* 第二次：用例子让它具体化
* 第三次：把它连接到听众的关切

**原因**：任何时刻约有 20% 的听众正在走神。不能假设“我说过一次，所以所有人都理解了”。

### 2. 围栏（Fence）

不要只说你的观点**是什么**，还要说明它**不是什么**，以及它与他人做法的关键区别。

创业示例：

```text
“这不只是另一个 SaaS 工具。它的核心是一款围绕数据网络效应构建的产品：
使用者越多，对每个人的价值就越大。
这与竞争对手 X 的商业逻辑完全不同。”
```

研究示例：

```text
“我的方法看起来可能和 Jones 2022 相似，
但关键差异是：他的方法复杂度是指数级的，而我的方法是线性的。”
```

### 3. 口头标点（Verbal Punctuation）

定期宣布你在演讲中的位置，让分心的听众知道如何重新跟上：

* 列举：“这是第二点。”
* 回顾提纲：“我们已经讲过开场和核心问题；现在进入第三部分：我们的解决方案。”
* 明确标记转折：“到目前为止我们讨论的是 *why*；现在转向 *how*。”

### 4. 提出问题

在重要节点插入问题：

* 不能太容易，否则人们会感到尴尬
* 不能太难，否则没人会回答
* 提问后停顿 5 到 7 秒。这段沉默是合理的，不要急着自己回答。

## IV. 工具选择策略

| 工具 | 最适合 | 主要优势 | 常见错误 |
| --- | --- | --- | --- |
| **黑板 / 白板** | 教学、推导、现场解释 | 节奏匹配听众的吸收速度；让双手有事可做；支持视觉构建 | 写得太小；没有清楚地擦除 |
| **道具 / 实物演示** | 创造记忆点；让抽象内容具体化 | 听众可以通过体感理解；非常容易记住 | 把道具变成噱头 |
| **幻灯片** | 会议演讲、求职演讲、路演、展示结果 | 结构清晰；适合数据和图表 | 文字太多；字太小；照着屏幕念 |

### 幻灯片设计硬规则

```text
✅ 每页一个核心信息
✅ 正文至少 40pt；35pt 是绝对下限
✅ 图片 > 文字；文字 > 项目符号
✅ 合作者放在开场页，不要放在最后一页
✅ 最后一页标题应为“Contributions”，而不是“Thank you”
✅ 不使用激光笔——直接在图上放置箭头

❌ 不要照着幻灯片上的文字念
❌ 不要用杂乱内容填满幻灯片背景
❌ 一页不要放超过三个关键点
❌ 不要为了“塞进更多内容”而使用小字号
❌ 不要使用激光笔（它会破坏与听众的眼神交流）
```

## V. 特殊场景作战手册

### 场景 A：创业招募 / 说服联合创始人

核心任务：在短时间内让对方相信：
（1）这个问题值得解决；
（2）你的方法有原创性；
（3）你已经验证了某些重要事情。

**结构模板：**

```text
1. [30 sec] 对方会立即认出的痛点
2. [30 sec] 为什么现有解决方案仍然不够
3. [1 min] 你的洞察和差异化角度
4. [1 min] 你已经验证的最重要结果
5. [1 min] 为什么现在是时机，以及为什么你们是合适的团队
6. [Closing] 你希望对方采取的一个具体行动
```

**关键提醒：**

* 不要堆叠所有功能。呈现最能建立信任的一个结果。
* “为什么是你”比“为什么是这个方向”更重要。
* 以具体行动号召结尾，不要说“以后有空聊聊”。

### 场景 B：研究演示 / 组会 / 进度汇报

**结构模板：**

```text
1. [Opening] 重新说明为什么这个问题重要（不要假设每个人都记得）
2. [Background] 上次讨论停在哪里 / 之前的状态
3. [Core] 这次有什么新内容：结果、发现或遇到的问题
4. [Analysis] 这些结果意味着什么，以及它们支持还是挑战你的假设
5. [Next step] 下一步要做什么，以及需要什么支持
```

**定位原则**

不要只说“我做了什么”，还**必须**说清楚：

* 这个问题在更广泛领域中的位置
* 其他人是否做过，以及他们做到什么程度
* 你的工作在哪个维度上推动了进展

**口试 / 答辩补充说明：**

* 和完全不了解你研究的人练习，让他们尖锐地提问
* 你的导师不是最佳练习听众，因为他们会在脑中补全你没解释清楚的内容
* 答辩委员会越资深，越不容易提出带敌意的刁钻问题；年轻评审往往更严厉

### 场景 C：求职演讲 / 学术面试

**黄金规则：前 5 分钟内必须同时建立以下两点：**

1. **愿景（Vision）**：你正在解决一个值得关心的问题，并且有独特角度
2. **已经做成的事（Done Something）**：你不只有想法，已经取得具体结果

**结构（夹心模型）：**

```text
[Opening 5 minutes]
  → 提出人们真正关心的问题
  → 解释你的方法有什么新意
  → 快速指出你已经取得的具体结果

[Middle]
  → 列出实现愿景所需的关键步骤
  → 解释哪些步骤已经完成，以及每一步产生了什么具体结果
  → 系统演示（如适用）

[Ending]
  → 最后一页：Contributions（列举贡献）
  → 这是夹心模型的另一片面包，与开场呼应
```

**常见错误：**

* 开头花太长时间讲背景，5 分钟后听众仍不知道你在做什么
* 把结果藏在中段，导致听众直到最后才知道你究竟是否完成了什么
* 最后一页塞入很长的合作者名单，稀释自己的贡献

### 场景 D：说服 / 提案 / 向上汇报

**核心原则：先回答最重要的问题，再提供支持**

在听众心里，尤其是领导心里，优先顺序是：

1. 这为什么和我有关？
2. 结论是什么？
3. 你需要我做什么？

建议结构：

```text
1. 先给结论（说明你希望得到的结果或建议）
2. 给出三个最有力的理由（每个理由配一个具体证据）
3. 承认并回应主要担忧
4. 明确提出下一步行动请求
```

## VI. 让作品被记住：Winston 之星

如果你希望作品在某人的脑海里留下印记，检查以下五个维度是否都存在：

```text
           Symbol
               ▲
               │
Story ◀──── Salient ────▶ Slogan
               │
               ▼
           Surprise
```

| 维度 | 定义 | 示例 |
| --- | --- | --- |
| **Symbol** | 代表你作品的具体图像或概念 | “arch”；“one figure”；“one number” |
| **Slogan** | 让人记住你做什么的一句话 | “one-shot learning”；“earlier than a human ophthalmologist” |
| **Surprise** | 违反直觉的发现或结果 | “你不需要一百万个样本；一个例子就能教会你一些东西” |
| **Salient Idea** | 最清楚地突出的一个点，不一定最重要，但最显眼 | “near miss”——几乎正确但并不正确的东西，往往最有信息量 |
| **Story** | 你如何完成它、为什么重要、过程中最关键的是什么 | 让经历变得易懂，而不只是展示结果 |

每次重要演示前，用这颗星自检：**听完你说的话，对方能否用这五个词复述你的工作？**

## VII. 设计结尾

### 最后一页

不要放：

* 很长的合作者名单（应放在第一页）
* “Thank you” 或 “Q&A”
* 空白页

**应当放：Contributions（贡献）**

格式：

```text
## Contributions

1. Proposed [a problem / framework / definition]
2. Built [a system / method / dataset], achieving [result] on [metric]
3. Revealed [a finding], with [impact] on [the field]
```

这页会在问答期间保持可见，因此**它仍然在替你说话**。

### 最后一句

不要以“Thank you for listening”结尾。这会隐约暗示：“谢谢你出于礼貌坚持听完。”

更好的选择：

* 用笑话结尾（到最后听众终于进入你的节奏，因此幽默更有效）
* 向听众致敬：真诚说出你从这次交流中获得了什么
* 用有力的总结句结尾，然后保持沉默

## VIII. 常见高风险错误：快速自检

内容准备好后，逐行检查：

**内容**

* [ ] 开场包含赋能承诺吗？（听众知道为什么**应该**听吗？）
* [ ] 核心观点出现了 2 到 3 次吗？
* [ ] 清楚说明了这**不是什么**吗？（是否划出了边界？）
* [ ] 贡献是否清楚列举？

**表达**

* [ ] 演讲中有口头路标吗？（分心的听众能重新跟上吗？）
* [ ] 至少有一个问题吗？（它能产生参与吗？）
* [ ] 演讲传达了真实激情吗？（不是表演，而是真实投入）

**幻灯片**

* [ ] 每页文字足够少吗？
* [ ] 字号至少 40pt 吗？
* [ ] 最后一页标题是 Contributions 吗？
* [ ] 合作者列在第一页吗？

**时间与地点**

* [ ] 你提前检查过场地吗？
* [ ] 灯光足够明亮吗？
* [ ] 练习听众是不理解你研究的人吗？

## IX. 使用本技能的工作流程

1. **说明场景**：解释这是什么类型的演示、听众是谁、你有多少时间
2. **提供现有材料**：草稿、提纲，甚至幻灯片截图都很有用
3. **说明目标**：说清楚你最担心什么（开场薄弱、结构混乱、难以理解、难以记住等）
4. **输出**：根据场景模板和诊断原则，提供具体的结构修改、措辞建议或完整草稿
