# 从内容到演示文稿的工作流

新建演示文稿或大幅重写时使用此工作流。

## 1. 解决源材料

确定确切的源材料并完整阅读。源材料中的图表、表格、定义、引用和附录若会影响演讲，也要跟进阅读。源材料可用时，不要凭记忆重构技术主张。

记录：

- 受众、场地、时间限制和期望结果；
- 核心问题或主张；
- 主要学习目标或决策目标；
- 必须保留的事实、推导、例子、限定条件和证据；
- 演示文稿所需的记号、图形、表格和引用；
- 提供的模板、示例演示文稿、品牌系统或格式约束。

## 2. 构建叙事

编辑演示文稿文件前先写幻灯片计划。对每张计划中的幻灯片记录：

- 观点或受众动作；
- 它所代表的源材料段落、方程、图形或证据；
- 计划采用的布局系列；
- 是静态内容还是渐进构建的一部分；
- 属于演讲者备注的细节。

不要逐页或逐文档章节一一转换。合并重复的铺垫，拆分密集论证，为困难观点提供足够视觉空间。除非改变能让现场讲解更清楚，否则保留源材料的逻辑。

一个有用的默认弧线是：

1. 陈述问题、疑问或张力。
2. 只引入受众需要的铺垫。
3. 展示限制、证据或利害关系。
4. 呈现关键观点、结果或提案。
5. 逐步讲解推理或证据。
6. 以具体结论、决定或下一步结束。

材料需要时使用不同弧线。

## 3. 选择视觉来源

存在获批模板或示例演示文稿时，完整检查并以其作为布局、字体、间距、颜色和重复视觉元素的来源。复制并编辑合适的源页，不要重新搭建样式。

对于 PowerPoint 或 Keynote：

- 保留可编辑对象和继承的主题样式；
- 使用一个源演示文稿或主题；
- 不要导入与获批视觉系统冲突的库存布局。

对于 Beamer：

- 保留 `.tex` 源文件；
- 使用项目共享样式包；
- 不要在一套演示文稿中重新定义共享间距、颜色、方框或页面装饰。

## 4. 转化内容

- 每页只保留一个主要观点或教学动作。
- 如果有助于论证，把标题写成结论、问题或过渡。章节分隔页使用简洁的主题标签。
- 解释方程、图形或结果证明了什么，而不仅仅是它是什么。
- 按照口头说明的节奏分步展示长推导。
- 源图形清晰时复用。只有原图无法用于幻灯片时才重画。
- 裁切图片时不要拉伸。
- 在可读页脚或演讲者备注中引用外部图形、结果和引文。
- 受众不需要同时阅读时，把限定条件和证明细节移到备注。
- 绝不编造数据、引用、例子或结论来填满幻灯片。

## 5. 构建与验证

使用适合文件格式的工具构建。实际可行时，把临时渲染文件和工作文件放在最终产物目录之外。

然后渲染完整演示文稿，并使用 [visual-design-review.md](visual-design-review.md)。以完整尺寸检查每一页，包括叠加层创建的每一张实体页面。修正缺陷，重新渲染并再次检查。

## 6. 记录反馈

审阅后记录用户的确切反馈，以及它只适用于这套演示文稿还是未来演示文稿。把重复反馈转化为简洁的一般规则，但不要抹去原始关注点。
