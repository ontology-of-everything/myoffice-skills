# 演示文稿制作

把源材料转化为面向受众、适合现场讲解的演示文稿。在保持技术准确性的同时，让论证比单独阅读源材料更容易跟上。

## 按需加载详细指导

- 创建新演示文稿或大幅重构现有演示文稿前，阅读 [deck-workflow.md](references/deck-workflow.md)。
- 选择视觉系统、设计布局或审阅渲染后的幻灯片时，阅读 [visual-design-review.md](references/visual-design-review.md)。
- 只修改少数现有幻灯片的文字时，仅使用下面的核心规则，不必加载两个参考文件。

## 核心规则

- 构建前确定受众、目的、场地、时长、源材料和所需输出格式。
- 阅读与演讲相关的完整源材料。不要编造主张、例子、结果、方程、引用或引文。
- 修改演示文稿前规划叙事和每页的任务。
- 每页只有一个主要观点或教学动作。
- 有可用的既定演示文稿或模板时，以它作为视觉来源。保留其字体、页边距、颜色和页面装饰。
- 维持单一视觉系统。不要混用主题，也不要凭记忆重建已提供的样式。
- 比起密集散文，优先使用图表、方程、图形、曲线和具体证据。不要添加装饰图片。
- 可读文字要短到能在演讲距离阅读。把交付需要、但不应同时阅读的细节放入演讲者备注。
- 完全保留记号。数学使用真正的上标、下标、撇号、极限和条件记号进行渲染。
- 只有每一步都能帮助口头说明时才使用渐进构建。
- 保持源文件可编辑。保留 PowerPoint 对象或可编译的 Beamer 源，而不是把演示文稿扁平化为图片。
- 交付前渲染并检查每一页。修复裁切、溢出、意外重叠、文字过小、间距不一致、图像变形、残留占位符和不可读引用。

## 工作流

1. 解决源材料和约束。
2. 写出每页的幻灯片计划，记录观点、证据、布局和构建行为。
3. 选择视觉来源，并将计划中的幻灯片映射到合适的布局系列。
4. 使用适当的演示工具构建可编辑演示文稿。
5. 渲染完整演示文稿，检查每张实体幻灯片或叠加层。
6. 修正缺陷、重新渲染，重复直到审阅通过。
7. 报告最终演示文稿路径和未解决的内容问题。

用户提供反馈时，保留其确切关注点，并将重复反馈转化为后续演示文稿可复用的简短规则。
