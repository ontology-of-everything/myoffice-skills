# 演示风险模式

## 风险级别

- **低：**依赖少，失败容易口头替代。
- **中：**有明确依赖，截图或录屏可以替代。
- **高：**多项外部依赖或失败会打断关键论证。
- **严重：**演示就是核心证据，无法简单替代。

## 演示类型与画像

### 依赖网络的演示

依赖网络可用性、延迟或远程服务。准备离线录屏和截图，提前确认连接。

### 依赖认证的演示

依赖登录、令牌、权限或账户。使用演讲专用账户，提前登录并准备脱敏录屏。

### 本地工具演示

依赖特定版本、环境或配置。锁定环境，准备可运行副本和代码走读。

### 第三方 API 或服务演示

依赖外部服务、配额或服务状态。记录成功结果，准备截图和本地固定响应。

### 现场编码演示

依赖输入、编辑和运行过程。提前准备骨架、检查点和最终代码；失败时切换到代码走读。

### 基础设施或部署演示

依赖云资源、权限和部署时间。提前部署并录制；准备展示日志和最终状态的截图。

### 硬件或实体演示

依赖设备、电源和现场空间。准备备用设备、视频和口头说明。

## 一般原则

每个演示都列出依赖、失败模式、备用方案和准备检查表。备用层级按录屏、截图讲解、代码走读、口头描述排列。明确失败时要说的话：将其框定为“这正说明系统为何需要 X”，继续推进论证，不要现场反复重试。
