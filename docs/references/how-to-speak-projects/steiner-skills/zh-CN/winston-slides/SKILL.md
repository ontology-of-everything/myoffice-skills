# Winston 幻灯片

本技能将 Patrick Winston 的 MIT 讲座 *如何演讲*（1985–2018）应用于幻灯片内容——审计现有演示文稿或起草新的演示文稿。精选内容剔除了不适用于现代幻灯片工具（Marp、Google 幻灯片、带母版模板的 PowerPoint）或非终身教职场景的规则：40 磅字号教条、反品牌立场、反激光笔、求职演讲三页框架和实体道具。

保留的，是确实能让学术、工作坊和讲座受众更清楚地理解幻灯片的部分。

## 模式检测

本技能有两种模式。开始时先决定模式：

- **审计模式**——用户已有幻灯片（文件、粘贴内容、描述或 Google 幻灯片 链接）。任务是找出 Winston 会修改什么。
- **构建模式**——还没有幻灯片，只有意图（“我必须做一场关于 X 的演讲”）。任务是访谈用户、做轻量研究并起草幻灯片提纲。

情况含糊时，询问：*“你已经有想让我审阅的幻灯片，还是要从零开始？”*

## 起飞前：语言和格式

在产出提纲或审计前，要确定输出语言和幻灯片格式。不要仪式性地同时询问；先检查输入，只在确实含糊时询问。开头的阻力会让技能显得官僚。

- **输出语言。**如果用户的消息明显是德语（英语或其他语言也一样），就默默跟随。输入所用的语言就是答案。只有语言不清楚，或用户明确暗示受众是多语种时才询问。
- **幻灯片格式。**如果用户说了格式（“Marp deck”“Google 幻灯片”“outline”），或已有演示文稿暗示格式（例如审阅带 Marp frontmatter 的 `.md`），就默默使用。否则默认使用**与格式无关的提纲**——使用 `[SLIDE N]` 标题的普通 Markdown。这是承诺最低、也最容易后续转换的格式。只有用户直接询问格式，或选择特定工具（Marp HTML 导出、DHCraft Apps-Script 导入器）会明显影响产出时才询问。

可产出的三种格式：

- **与格式无关的提纲**——普通 Markdown，以 `[SLIDE N]` 为标题，每页一个小节，适合工具决定尚未确定时的思考。
- **Marp Markdown**——标准 Marp 约定（`---` 分隔符，必要时使用 `<!-- _class: -->` 指令），适合渲染成 PDF/HTML 的临时演示文稿。
- **DHCraft Google 幻灯片 格式**——遵循 `marp-slides` 技能：最少 Marp frontmatter，通过 `<!-- _class: cover -->` / `<div class="columns">` 映射布局，章节页使用单独的 H1，使用 en dash（不用 em dash），适合经过 DHCraft Apps-Script 导入器的演示文稿。

## 审计模式工作流

1. **取得幻灯片内容。**用户粘贴就直接使用；引用文件就读取；口头描述时，请其提供 3–5 页最重要幻灯片的实际内容——Winston 审计是具体的，不是抽象的。
2. **分类每页。**分为*承重页*（章节开头、关键定义、演示介绍、结论）或*支撑页*（概览、列表、过渡）。5S 测试只适用于承重页；幻灯片罪行适用于所有页。
3. **运行 Winston 启发式**（见下文）。每个发现都给出具体修复，而不只是标记。“减少文字墙”没有用；“把方法论项目符号拆成一页，结果表放到新页”才有用。
4. **识别结尾页。**这是最常被违反的规则。如果是“谢谢”或“问题？”，提出带具体祈使句的贡献式替代方案。
5. **报告结构。**使用以下布局：
   ```
   ## 审计摘要
   - 审阅 N 页，标记 M 页
   - 一句话结论

   ## 逐页发现
   [每个被标记页面：问题、原因、具体修复]

   ## 横向建议
   [跨多个页面的模式]

   ## 结尾页
   [必要时给出贡献式改写]
   ```

## 构建模式工作流

1. **确定三个锚点——主题、受众、赋能承诺。**起草前需要：
   - **主题：**一句话说明演讲讲什么。
   - **受众：**谁在房间里，已经知道什么，关心什么。
   - **赋能承诺：**结束时他们应能*做到*什么，而开始时不能。

   检查用户初始消息已提供的内容，只询问缺失项。如果用户已经说“给系统管理员做 25 分钟演讲，最后他们要批准”，三者都已存在；提取后继续。访谈是填补空白，不是强制门槛。
2. **轻量研究。**主题陌生或技术核心需要核验时，快速搜索网络，用真实来源支撑内容而不是编造。若用户就是领域专家并提供实质内容，则跳过。
3. **起草提纲。**第 1 或第 2 页以赋能承诺开头。对承重页应用 5S 测试（标记哪些是有意识应用的）。以包含一个具体祈使句的贡献页结束。
4. **交还用户。**简要说明哪些页是承重页、演示文稿的核心惊喜是什么，以及哪些开放问题仍待解决（例如“我用占位数据起草了第 7 页——请换成真实数字”）。

## Winston 启发式（精选）

### 赋能承诺

每个章节或演讲开场都回答：*“听完这一节，受众能做什么是此前不能做的？”*

不要说“我们将讨论 X”，而要说“你将能够做 Y”。如果计划的开场无法改写为“听完这一节你可以 ___”，它就太弱。这是幻灯片中杠杆作用最大的单一干预。

### 承重页的 5S 测试

承重页包括章节开头、关键定义、演示介绍、转折点和结论。**不是**每一页——概览、过渡和材料列表不适用。

承重页至少应满足五项中的**两项**：

- **符号**——具体的视觉或语言锚点（命名指标、反复图像或定义短语）。
- **口号**——受众无需解释就能引用的可复述短语。
- **惊喜**——反直觉转折，颠覆受众已有假设；仅仅*有趣*不算，必须产生矛盾。
- **醒目观点**——幻灯片留下的*一个*观点；相互竞争的观点要删掉，不要并列排序。
- **故事**——简短说明为何或如何重要。一句话足够，不要轶事块。

满足四或五个 S 的幻灯片很少见，也非常强。大多数优秀承重页命中两个。

### 幻灯片罪行

幻灯片有以下任一行为即违规：

- **文字墙。**正文超过约 40 个词。比较是重点时表格可以更密，但绝不能用表格作为散文布局技巧。
- **配音。**演讲者会逐字念出的文字。幻灯片和演讲应互补而非重复。
- **开场缺少赋能承诺。**第 1 或第 2 页若没有兑现“听完这一节/演讲你可以 ___”，开场就失败了。议程项目符号（“我们将讨论 X”）不算——它描述演讲者的计划，不是受众获得的新能力。
- **“谢谢 / 问题？/ 联系方式”作为唯一结尾页。**这是最常见也最容易修复的罪行。结尾页在问答期间停留最久——把它浪费在“谢谢”上，受众离开时什么也没带走。替代模式见下方**贡献式结尾**。
- **复述复述过的内容。**只重新列出早先主张的结论。综合需要新陈述，而不是重述。

### 贡献式结尾

这是“谢谢/问题？”的替代方案。这个结尾罪行同时最常见、也最容易修复，因此替代方案成为命名模式，审计和构建模式都可直接使用。

贡献页分为两半：

1. **受众现在拥有的东西**——两到四个项目符号，是已兑现的赋能承诺。不是重复幻灯片标题，而是受众离开时获得的具体新能力。
2. **一个具体祈使句，带截止时间或对象。**受众可采取的单一下一步。不要写“有兴趣请联系”——应类似于 *“请在本周结束前通过邮件告诉我‘批准’或‘满足 X 才批准’”* 或 *“选一个工作流，在两周内按检查表跑一遍”*。

联系方式（邮箱、账号）可以保留，但要作为祈使句的*锚点*，不能作为标题。祈使句才是标题。这一页会在问答时保持显示——确保此时可见的内容值得受众看十五分钟。

### 幻灯片是佐料

不确定某内容该放幻灯片，还是放演讲者备注/讲义时：放备注或讲义。

三层、三种密度预算：

- **幻灯片**——受众此刻必须*看到*的东西，预算最紧。
- **演讲者备注 / 作战手册**——演讲者必须*知道*的东西，中等预算。
- **讲义 / 带走材料**——演讲后应能*重新阅读*的东西，预算最宽。

审计中常见的操作是把内容从幻灯片*降级*到备注，而不是删除。信息仍然可用，只改变视觉表面。

## 本技能有意不执行的内容

这些 Winston 规则与现代幻灯片环境冲突，因此有意精选排除：

- **最小 40 磅字体**——Marp、PPT 母版和 Google 幻灯片 模板统一管理排版，而非逐页管理；强制 40 磅会覆盖主题。
- **反品牌立场**——母版中的页眉、页脚和徽标是功能，不是违规。
- **反激光笔**——这是投影/视听问题，不是幻灯片内容问题。
- **实体道具/演示**——纯数字演示文稿无关；现场编码或现场演示是现代等价物，不需要单独规则。
- **求职演讲三页框架**（愿景 / 工作证明 / 贡献）——针对终身教职轨道。大多数用户制作工作坊、讲座或推介演示文稿，这个脚手架不合适。

如果用户明确调用这些已排除规则（“我想严格用 40 磅”），就听从用户——其具体情况可能确有理由。
