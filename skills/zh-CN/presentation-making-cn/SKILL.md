# 演示文稿制作

让听众带走一个有依据、能复述的核心主张。默认制作现场演示用的单文件 HTML，配逐页讲者备注；可选完整 Markdown 或独立阅读模式。制作由本技能独立承载，无必需脚本或外部技能。

## 核心概念

- **目标改变**：听众结束后应新增的理解、能力或决定，是内容取舍的依据。
- **核心主张**：回答目标问题的一句话；证据决定它能说多大。
- **赋能承诺（empowerment promise）**：开场明确听众将获得什么，并由正文与结尾兑现。
- **记忆抓手**：将图示、短语、对比或故事连接到主张及依据的线索；记住装饰而忘记主张不算成功。
- **塑形**：从候选方向中确定主张、证据、边界、叙事和记忆抓手；先决定讲什么及为什么，再安排页面。
- **对齐**：由用户裁断影响结果的选择；已确认的选择持续有效，局部创作与修正由代理推进。

## 工作准则

- 先读材料、已有决策与授权；事实自行查证。每轮提出前置条件已满足、仍需用户裁断的全部关键问题，附推荐答案、依据与代价，等待回答；后置问题留到下一轮。已决或已授权事项直接推进。
- 分清事实、推断和待定选择。可补充公开权威来源并记录出处；内部材料不直接用于外部检索。缺证据时补证、缩小主张或标记待补，不能编造。
- 原则是有适用条件的判断依据。冲突先按事实和用户目标处理；仍无法判断时解释取舍并请用户决定。推荐不等于用户已同意。
- 默认维护一份轻量 `presentation-work.md`；用户选择不落盘时，在对话保留相同摘要。按当前阶段读取材料，原始材料保留路径，不反复展开全文。

## 阶段与读取时机

新建文稿按下表推进；改稿从最早受影响的阶段进入，保留已成立的决策。每阶段达到退出条件才推进，避免一次性生成压过未决问题。

| 阶段 | 行动与退出条件 | 此时读取 |
| --- | --- | --- |
| 理解 | 核查相关材料；提出听众、目标改变、时长、场景、证据边界及缺口。关键目标获得确认 | [过程与对齐](references/process.md) |
| 头脑风暴 | 提出有实质差异的候选方向，比较证据、听众价值与记忆潜力；已有明确方向时直接压力测试 | [原则与范式](references/winston.md) |
| 塑形 | 确定承诺、核心主张、证据链、概念边界、记忆抓手及舍弃项。方向获得确认 | 延用当前两份参考 |
| 大纲 | 每页确定职能、主张或问题、证据来源、视觉关系、备注任务与时间；规划回扣、过渡、互动、收束。结构获得确认 | 延用当前两份参考 |
| 创作 | 按确认的大纲生成完整正文与备注；保留模板和品牌约束，稳定页 ID 随重排保留 | [输出约定](references/output.md) |
| 检视与重构 | 核对事实、理解、记忆与实际产物；定位问题所属阶段，修复并复验受影响内容 | [质量检视](references/review.md) |

## Winston 原则如何落地

| 原则 | 在产物中的作用 |
| --- | --- |
| Empowerment promise | 开场给出具体所得；正文支撑；结尾让所得可复述 |
| Cycling | 用概念、实例、应用等不同角度重访核心，每次增加理解 |
| Fence | 借对比或近似反例，区分容易混淆的概念与方案 |
| Verbal punctuation | 在转折处说明已建立什么、接下来解决什么，让走神者能重新跟上 |
| Ask and wait | 向听众提出可思考的问题，备注注明等待、预期答案与无人回应时的接法 |
| Ending | 回到开场承诺，留下有证据的所得和记忆抓手；按目标决定是否提出行动 |

这些原则的应用位置可以在正文、视觉或备注中；按情境使用，不要求每页齐备。向用户提问用于决策，向听众提问用于理解，两者分开。细节、正反例与可选 5S 见阶段参考。

## 完成条件

交付的是可用文稿，不是大纲。关键主张有依据，承诺得到兑现，听众能跟上；记忆抓手能引回主张及关键依据，结尾强化这种联系；正文与备注符合场景和时间预算；所选格式通过实际可执行的检查。

审查发现的问题须修复并复验。改变目标或超出已有授权的重大方向变更回到用户对齐；材料或工具缺失时明确未验证项与继续所需条件，不宣称通过。完成后给出成品路径、简短检视结论及真实限制。真实记忆效果须由听众反馈验证，代理检视只证明设计具备相应条件。
