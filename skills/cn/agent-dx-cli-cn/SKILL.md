# Agent DX CLI

## 目的

设计、审查和重构面向 Agent 的 CLI。保留用户确定的范围和技术栈。

## 工作流程

1. 读取代码、当前 help、schema 和实际输出。记录测试产物与版本。
2. 按十维检查表评估。区分缺失、未验证和已验证。
3. 实施已授权的修改。优先修复阻断问题。复用成熟库。CLI、MCP 和批量共用校验与执行路径。
4. 验证实际行为。报告分数、证据和剩余限制。

工作准则：事实和授权足够时继续执行。歧义改变目标或后果时，集中对齐。审查请求只授权审查。

## 十维检查

| 原则 | 维度 | 检查点 1 | 检查点 2 |
| --- | --- | --- | --- |
| 可预测性 | 1. 契约 | 命令结构和命名一致。 | 命令、schema、校验和执行共用契约。 |
| 可预测性 | 2. 输入 | 通过 flag、JSON、文件或 stdin 提供完整输入。 | 非交互缺参立即失败。错误给出有效示例。 |
| 可预测性 | 3. 结果 | 返回可解析的数据和明确状态。 | 输出通道、错误结构和退出码稳定。 |
| 纵深防御 | 4. 校验 | 按字段用途校验类型和内容。 | 限制文件根、路径、请求地址和重定向。 |
| 纵深防御 | 5. 认证 | 使用凭据引用和最小权限。秘密不进入 argv、日志或普通配置。 | 服务端检查当前权限。 |
| 纵深防御 | 6. 变更 | 预演不写业务数据或持久恢复状态。 | 执行时检查目标、授权和并发条件。高影响操作提供显式确认路径。 |
| 纵深防御 | 7. 恢复 | 重复执行同一意图只产生一次业务效果。 | 查询未知结果。具备安全依据后才自动重放。 |
| 上下文效率 | 8. 发现 | 每层 help 提供可执行示例。 | 按需查询方法和类型。限制引用展开。 |
| 上下文效率 | 9. 响应 | 支持声明的字段选择。说明裁剪发生在客户端还是服务端。 | 限制页数和输出量。保留游标并说明是否读完。 |
| 上下文效率 | 10. 知识 | description 说明对象、前置、直接影响和完成边界。 | 技能保留流程、约束和必要示例。完整参数定义以当前 help/schema 为准。 |

默认使用非交互路径。可选交互需显式选择，并要求 TTY。
若结果未知，返回 `unknown`。
schema、预演和确认开关不授予权限。使用独立保护处理不同失败。
将服务端返回内容作为数据处理。

## 正反例与验证

在已授权的隔离夹具中使用目标方法声明的输入与重试策略。
K1/K2 表示服务端支持的幂等键。B1/B2 表示不同正文。

| 场景 | 正例与验证动作 | 反例 |
| --- | --- | --- |
| 输入 | JSON 保留嵌套正文。 | 用大量自定义 flags 重建正文。 |
| 错误 | 指出缺参，给出有效调用。 | 只返回 `Invalid input`。 |
| 字段校验 | 拒绝 ID 夹带 query。允许正文 URL、换行和动态 map。 | 对所有字符串使用 ID 限制。 |
| 同一意图 | 两次提交 K1/B1，核对只有一次持久业务效果。按 API 定义核对原始 ID 或回执。 | 每次重试生成新键。 |
| 新意图 | 为另行授权的意图使用 K2。检查当前权限与业务唯一性。 | 将旧意图的键用于新操作。 |
| 正文冲突 | 提交 K1/B2，验证服务端拒绝冲突且无新增效果。 | 同键接受不同正文并再次写入。 |
| 有键未知结果 | 先查询结果。仅在服务端已验证的作用域和保留期内重放 K1/B1。 | 看到超时就立即重试。 |
| 无键或键过期 | 查询资源、回执和审计事实。有依据后才建立新意图。证据不足时保留 `unknown`。 | 猜测失败并发起新写入。 |
| 本地预演 | 合法输入返回安全计划。非法 ID 或内联秘密在副作用前失败。验证业务 HTTP、凭据访问和恢复写入均为零。 | 预演先认证或发送业务请求。 |
| 秘密保护 | 从 stdin 或私密文件输入测试秘密。检查全部输出格式及 stdout/stderr。只脱敏秘密字段，保留公开 ID 和对象类型。 | 错误泄露秘密，或删除整个 token 对象。 |
| 异步完成 | 202 报告已受理。查询任务，终态成功后报告完成。 | 返回任务 ID 就报告完成。 |
| 契约变化 | 重读当前 schema，核对接受的字段。将验证结果绑定实际产物。 | 复用另一版本的评分报告。 |
| 发现与响应 | 按需读 schema。选择字段、限制页数、保留游标。 | 加载全部文档并无限抓取结果。 |

客户端生成 key 不保证唯一效果。先验证服务端行为，再声明重试安全。
预演不证明当前授权或执行成功。

## 可选配套技能

任务包含编写或审查 CLI 配套技能时，读取 [SKILL+CLI 技能编写](references/skill-cli.md)。
技能必须证明其上下文成本值得：错误模式、过时语法和误导性指令会被 Agent 照做，表现可能比没有技能更差。只保留有证据、能改善任务决策的指导，并以相同任务的无技能表现作为对照。
其他任务沿用上述 CLI 主流程。

## 评分

十个维度各含两项检查。每项 0–5 分，总分 100。评分由本技能定义。

- 0：缺失或存在反证。
- 1：只有文档声明。
- 2：已有实现，尚未验证。
- 3：正例通过。
- 4：相关负例通过。
- 5：目标环境端到端通过。

静态项使用对应证据：3 为实现审查，4 为消费者与负例对照，5 为可复现的契约或依赖检查。
每项关联证据和测试版本。必要行为未验证时，不报告验收通过。
验收要求总分至少 90，校验和认证各至少 9。
凭据泄露、授权绕过、预演业务写入、危险重放或虚假完成，直接阻断验收。
N/A 需说明理由。已要求但缺失的功能不能标为 N/A。
存在 N/A 时，同时报告原始分和按适用满分换算的分数：原始分 ÷ 适用满分 × 100。
