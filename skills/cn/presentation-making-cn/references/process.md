# 过程与对齐

## 理解材料

阅读与任务相关的原始内容，保持数据口径、时间范围、引用语境和不确定性。建立最小映射：来源位置 → 可支持的主张 → 限制。将用户意图与材料结论分开：用户希望证明的事，不一定已被证据证明。

先从材料填写简报：听众及已有认知、目标改变、时长与互动预算、现场演示或独立阅读、HTML 或 Markdown、品牌与必讲内容、证据缺口。只问影响后续选择的未知项。

公开资料优先原始研究、官方报告或一手文档，记录链接、日期和适用范围；未提供内部事实时向用户索取所需信息。相互冲突的来源保留冲突及其影响，不能偷偷选择更好听的数字。

## 追问决策，而非收集表格

把选择组织为依赖树：目标与听众 → 主张和取舍 → 叙事及记忆抓手 → 逐页结构。每轮只问前置已解决的决策；同一轮可包含多个相互独立的问题。调查可以继续，依赖未决答案的创作等待。

每题采用：**问题与冲突 → 推荐答案 → 材料依据与代价 → 用户裁断**。推荐必须具体到当前内容；依据不足时明确条件，推荐一个暂定选择或核查办法。不给虚构的确定答案。

弱：你喜欢什么风格？

强：这场 10 分钟汇报是让委员会批准试点，还是理解技术？推荐以“是否批准小范围试点”为目标：现有材料能支持风险边界，尚不能证明全面收益；代价是压缩技术背景。

通常需确认三处：目标简报、塑形方案、大纲。用户已在材料或前文确认时直接继承；一个回答解决多个节点时合并记录。用户授权代理决定某节点时记录授权，勿继续索要同一确认。影响主张或重大结构的审查发现重新对齐，局部修正自行完成。

已有授权同样适用于重构：在授权范围内纠正不实措辞、收窄到证据支持的结论并说明理由；只有改变目标或超出授权的取舍才需重新裁断。用户的创作偏好不能把缺乏依据的陈述变成事实。

## 头脑风暴与塑形

从材料提出少量有实质区别的方向，例如问题驱动、案例驱动、关键对比驱动。每个候选给出主张、可用证据、听众所得、记忆抓手及主要弱点；不用换标题冒充不同方案。

用四问压力测试候选：证据最薄在哪里？听众最可能反驳什么？容易误解成什么？只能留下一个认识，应是哪一个？

收敛成一份塑形决策：赋能承诺；一句核心主张；支持它的证据与限制；需要的 fence；记忆抓手及其与主张的联系；叙事方向；明确舍弃的内容。陈列优势不足以构成论证，故事不能代替证据。

## 大纲与时间

每页记录：稳定 ID、职能、主张或思考问题、证据位置、视觉关系、备注任务、估计时长。视觉关系写“比较两种流程的等待环节”，比预先指定“三栏卡片”更有用。

从听众理解的依赖关系排序。安排 cycling 的不同角度、fence 的必要位置、章节接缝及观众问题。收束页与开场承诺相互核对。总时间包含开场、过渡、互动等待、演示和结尾；标出超时时可删内容，保护核心论证。

独立阅读模式把口头才解释的必要逻辑移入正文，把现场等待改成可停下思考的问题与稍后答案，仍保留回扣与概念边界。

## 轻量工作记录

默认只维护 `presentation-work.md`，内容是当前有效状态，不是聊天转录：

```markdown
# 当前简报
听众 / 目标改变 / 时长 / 模式 / 格式 / 约束
## 材料索引与证据缺口
来源位置 / 支持什么 / 限制
## 已确认决策
承诺 / 核心主张 / 记忆抓手 / 取舍 / 用户授权
## 当前大纲
页 ID / 职能 / 观点 / 来源 / 视觉关系 / 备注任务 / 时间
## 继续位置
当前阶段 / 未决问题 / 下一步
## 检视状态
问题 / 影响页 / 修正 / 复验结果或未验证原因
```

阶段结束更新摘要；替换失效结论，必要时简记变更原因。恢复工作先读此文件，再定位当前所需来源和参考。完成某阶段不禁止回退；回退后同步修正受影响的大纲、页面、备注及检视状态。
